# APORIA

**An experimental AI research lab that treats *how an agent thinks* as the experimental variable.**

Five reasoners start from the same philosophical question, on the same LLM. They run one cognitive engine with
explicit functions around the model: argument graph, metacognition, curiosity, counterfactual tests, adversarial
experiments, memory, formal tools and in-session learning. What differs is their cognitive policy. One parameter,
**Δ**, sets how far apart those policies are. The lab then measures how differently they reasoned.

**Live site (replays of the recorded runs):** https://derka1385.github.io/APORIA/

Built for Hack-Nation's 7th Global AI Hackathon, Challenge 3 *Agentic Scientific Discovery*.

> Research question: can explicit cognitive functions, orchestrated dynamically around an LLM, produce more diverse
> and meaningful reasoning trajectories than a single-pass or prompt-differentiated LLM?
>
> Hypothesis: Δ ↑ → reasoning-path diversity ↑ → argument diversity ↑ → unique objections ↑ → possibly different conclusions.

APORIA is neither a chatbot nor a multi-agent debate. No reasoner sees another's work, none is told to disagree, and
disagreement is measured, never rewarded.

## How it works

```
          ┌──────────── metacognition reads the graph ───────────┐
          │  "confident but weakly supported" → doubt            │
          │  "rests on a weak assumption"     → counterfactual   │
          │  "unresolved contradiction"       → adjudicate       │
          │  "not formally checked"           → formalize (tool) │
          ▼                                                      │
 controller: drive(op) = (state drive + signals) × policy weight × learned value
          ▼                                                      │
 attention: branch ~ softmax(curiosity / explore)               │
          ▼                                                      │
 operation (LLM call and/or tool) edits the graph, opens or resolves experiments
          ▼                                                      │
 learning: information gain → op value, branch yield ────────────┘
```

- **Twelve operations:** memory, reason, imagine, intuit, introspect, doubt, counterfactual, formalize, inquire,
  adjudicate, revise, conclude. Each is one LLM call or tool call that edits a typed argument graph.
- **Five profiles as policy vectors, not personas:** explorer, formalist, skeptic, synthesizer, minimalist. A profile
  sets about twenty parameters: op weights, controller and attention temperatures, sampling, context visibility,
  literature, memory and tool access, objections per doubt, adversarial damage, acceptance, rejection and stopping
  thresholds, budget.
- **Δ:** `param = base + Δ · (target − base)`. At Δ = 0 every reasoner runs the identical base policy and only seeds
  differ. That run is the noise floor.
- **Conditions:** `base` (identical policies), `prompt` (identical policies plus a persona sentence), `architecture`
  (Δ-scaled policies), `model` (a different model per reasoner).
- **Metrics:** path similarity (edit distance of operation sequences), branch diversity (Jensen–Shannon distance of
  node-type distributions), semantic diversity (best-match embedding coverage), unique hypotheses, assumptions and
  objections (no match at cosine ≥ 0.8 in any other reasoner), disagreement, conclusion similarity, plus per-reasoner
  research process (hypotheses rejected, experiments, defeats, information gain per step, compute per function).
- **Live state stream:** every cognitive event (attention, contradiction, rejection, insight, recall, tool) streams
  over SSE (`lab/STREAM.md`) to the lab UI and to the particle engine in `visual-engine/`.

Details: [`lab/ARCHITECTURE.md`](lab/ARCHITECTURE.md).

## Run it

Needs Python 3.10+ (standard library only) and an Ollama endpoint.

```bash
bash lab/run.sh                                  # local Ollama (qwen2.5:3b) → http://localhost:8740
```

On the evroc VM (Qwen3-30B), tunnel its Ollama and point the lab at it:

```bash
ssh -f -N -L 11500:127.0.0.1:11434 <user>@<vm>
OLLAMA_HOST=http://127.0.0.1:11500 APORIA_MODEL=qwen3:30b APORIA_PARALLEL=5 python3 lab/server.py
cd lab && python3 batch.py --full            # conditions plan;  --sweep for Δ 0/.25/.5/.75/1 × 2 seeds
python3 export_site.py                       # recorded runs → docs/ (the static site)
```

The batch stops as soon as the endpoint stops answering, and a run in which a reasoner's LLM calls mostly failed is
saved with a `failed` flag and never analysed.

**Visual engine** (React Three Fiber particle topology, simulated or live): `cd visual-engine && npm install && npm run dev`.

## Model-level differentiation with LobBot (next experiment)

[LobBot](https://github.com/OliverVillson/LobBot) compresses Qwen3-30B-A3B (61 GB) into a ~6.5 GB model for one task:
REAP expert pruning calibrated on task data, LoRA healing, per-layer quantization. Calibrated on one *cognitive
function*, each profile would keep different experts, so the reasoners would differ in their weights as well as their
policies.

```bash
cd lab && python3 lobbot_specs.py                # lab/lobbot/<profile>.taskspec.json, seeds = that profile's real outputs
lobbot run lab/lobbot/skeptic.taskspec.json --save          # on the GPU VM, ~25 min per profile
APORIA_MODELS="skeptic=<saved>,explorer=<saved>,..." python3 lab/server.py   # condition "model"
```

Status: TaskSpecs for skeptic (doubt), explorer (imagine), minimalist (introspect) and synthesizer (memory) are
built from recorded traces and validate against LobBot's schema. No compressed model has been run yet, so the lab
reports no compression result.

## Limits

- Small n: one or two runs of five reasoners per condition, on one question. Directions, not significance tests.
- Conclusions converge (conclusion similarity ≈ 0.9 in every condition). The process differs; the answer, so far, barely.
- Verdicts inside the loop (valid, survives, damage) are judgements by the same LLM. The truth-table check is real but
  only checks the model's own formalization.
- Similarity uses a small embedding model (nomic-embed-text). Compare conditions against the base noise floor.
